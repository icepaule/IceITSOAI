Überblick

IceITSOAI ist eine selbst-gehostete Offensive-Security-LLM-Pipeline für autorisiertes internes Security-Testing im Finanzsektor. Zu jedem Befund erzeugt sie ein Bedrohungsszenario, den realen Attack-Path (gemappt auf MITRE ATT&CK), einen validierungspflichtigen Proof-of-Concept sowie ein Mapping auf DORA, TIBER-EU, BaFin und EZB-Erwartungen — komplett ohne Cloud-Abhängigkeit, damit kein zusätzlicher ICT-Drittdienstleister im Sinne von DORA Art. 28–30 entsteht.

Compliance-Reporting

Jeder Befund folgt einem festen Schema: Asset/Scope → Threat Scenario → Attack Path (MITRE) → PoC → Impact → Regulatory Mapping → Remediation → Residual Risk.

Agentischer Operator

Ein CAI-basierter Operator führt autorisierte Schritte agentisch aus — mit Human-in-the-Loop-Freigabe vor jedem Befehl und vollständigem Audit-Trace.

RAG-Wissensbasis & Anreicherung

MITRE ATT&CK und regulatorische Dokumente als Vektor-Wissensbasis; automatische CVE-Anreicherung (CVSS/CWE/Referenzen) aus der NIST NVD gegen Modell-Halluzinationen.

Lokaler Threat-Intel-Korpus

Täglich aktualisierte Roh- und Index-Feeds (Exploit-DB, Nuclei, PoC-in-GitHub, Metasploit, CISA KEV, EPSS, ThreatFox, OTX) — referenzierbar mit Quellpfad, ohne flüchtige Web-Suche.

Architektur

Alle Komponenten laufen als Docker-Stack auf einem lokalen GPU-Host. Ein Security-Analyst arbeitet über Open WebUI mit Playbooks gegen die SecAnalyst-Modelle, ergänzt um RAG-Wissensbasis und Web-Recherche. Der CAI-Operator führt autorisierte Schritte agentisch mit Human-in-the-Loop-Freigabe gegen die Testziele aus. Ein täglich aktualisierter Threat-Intel-/Exploit-Feed sowie die NIST-NVD-API reichern Befunde faktenbasiert an.

Datenfluss einer Befund-Erzeugung

Der Analyst wählt ein Playbook und trägt Ziel/Netz/App ein. Open WebUI zieht passende Passagen aus der RAG-Wissensbasis, holt optional aktuellen Kontext über SearXNG und lässt das gewählte SecAnalyst-Modell den Befund im festen Compliance-Schema erzeugen. Für den agentischen Pfad plant der CAI-Operator Schritte gegen das autorisierte Ziel, lässt sich jeden Befehl vom Analysten freigeben und speist das Ergebnis zurück ins Modell für den nächsten Schritt — vollständig auditiert.

Quickstart

Grobe Reihenfolge für den Eigenbetrieb (Details siehe Repo-Dokumentation):

cp .env.example .env && $EDITOR .env        # Secrets/Ports/Host setzen

# 1) Modelle + Compliance-Modelfiles
bash bootstrap.sh

# 2) RAG-Wissensbasis (MITRE ATT&CK + Reg-Doku)
bash rag/load-knowledge.sh

# 3) Stack starten (Open WebUI, SearXNG, Qdrant, CAI-Operator)
docker compose up -d

# 4) Playbooks provisionieren
export WEBUI_TOKEN='...'
bash openwebui/provision.sh

# 5) Agentischer Operator — Rules of Engagement pflegen!
$EDITOR cai/scope.txt
docker compose exec cai-operator cai

Alle Platzhalter (Host, Ports, VLANs) sind vor dem Betrieb durch die eigene Umgebung zu ersetzen. Diese Doku-Seite und das Repo enthalten bewusst keine internen IPs, Hostnamen oder Zugangsdaten.
